## FINDINGS

### C04-GOV-005-F001 — S1 Major — 非核心/PROJECT Invariant 的 Supersession 链可终止于 `PROPOSED` 并被 Validator 错误判为 PASS

**Finding ID:** `C04-GOV-005-F001`
**Severity:** `S1 — Major`
**Status:** `OPEN`
**REGRESSION_OF:** `N/A`

**问题：**

`NON_REGRESSION_CONTROL.md` 明确定义：

* `PROPOSED` 尚未作为强制 Guard 生效；
* `LOCKED` 为当前有效并必须验证；
* `SUPERSEDED` 表示已经由新的显式 Invariant 替代；
* `LOCKED` Invariant 只能继续保持 `LOCKED`，或由新的记录显式替代为 `SUPERSEDED`。

但是当前 Validator 对“Supersession 活跃链最终必须落在 `LOCKED`”这一约束，只应用于硬编码的四个 `REQUIRED_FRAMEWORK_INVARIANTS`：

```text
NRC-FWK-001
NRC-FWK-002
NRC-FWK-003
NRC-FWK-004
```

证据位置：

```text
09_quality/non_regression/validate_non_regression.py:39-50
09_quality/non_regression/validate_non_regression.py:211-223
```

其中 `211-223` 的 active supersession chain 检查仅：

```text
for required_id in REQUIRED_FRAMEWORK_INVARIANTS:
    ...
    if current["status"] != "LOCKED":
        raise ContractError(...)
```

而实际 Guard 执行阶段又只选择：

```text
09_quality/non_regression/validate_non_regression.py:281-301

locked = [rule for rule in rules if rule["status"] == "LOCKED"]
```

因此：

1. `PROJECT` 范围中原本应受保护的 Invariant 可以形成：

   ```text
   LOCKED(old)
   → SUPERSEDED(old)
   → PROPOSED(new)
   ```

2. 后续新增、但不在四个硬编码 ID 集合内的 `FRAMEWORK` Invariant 也可以形成同样的无有效 `LOCKED` 终点链；

3. 这些链仍然可以通过 Contract structural validation；

4. `SUPERSEDED` old rule 不再执行 Guard，而 `PROPOSED` successor 同样不会执行 Guard；

5. Validator 最终仍可返回 exit code `0 / RESULT: PASS`。

这与语义 Authority 明确规定的状态语义和单调继承要求不一致：

```text
00_project/governance/modules/engineering/NON_REGRESSION_CONTROL.md:61-85
00_project/governance/modules/engineering/NON_REGRESSION_CONTROL.md:87-107
```

特别是：

```text
PROPOSED    = 尚未作为强制 Guard 生效
LOCKED      = 当前有效
SUPERSEDED  = 已由新的显式 Invariant 替代

LOCKED Invariant 只能保持 LOCKED，
或由新记录显式替代为 SUPERSEDED。
```

**独立负向复现实验：**

在不修改冻结 Target 的临时 fixture 中，分别构造：

```text
PROJECT:
NRC-PROJ-900 SUPERSEDED
  superseded_by: NRC-PROJ-901

NRC-PROJ-901 PROPOSED
  supersedes: NRC-PROJ-900
```

结果：

```text
PROJECT RC=0
RESULT: PASS
```

随后对非硬编码的新增 `FRAMEWORK` Invariant 构造同样的 `SUPERSEDED → PROPOSED` 链：

```text
FRAMEWORK_EXTRA RC=0
RESULT: PASS
```

因此该问题不是理论推测，而是当前 Validator 可稳定复现的 false PASS。

现有六项回归测试也没有覆盖此边界：

```text
09_quality/non_regression/test_validate_non_regression.py:46-101
```

当前六项测试分别覆盖：

1. current contract PASS；
2. Guard violation → `1`；
3. invalid contract → `2`；
4. 四个核心 Invariant 直接降为 `PROPOSED` → `2`；
5. Change Policy 弱化 → `2`；
6. Replacement Control 缺失 → `2`。

其“核心 Invariant 降级”测试只验证当前首个 required framework invariant，不覆盖 `PROJECT` 或未来新增 `FRAMEWORK` Invariant 的 Supersession 活跃链。

**影响：**

这是 Non-Regression Control 的系统性 fail-open 路径。

v0.1.9 明确支持 `FRAMEWORK / PROJECT` 两类 Invariant，并允许后续项目维护自己的 `project_invariants`。在当前实现下，一个已经进入治理保护范围的 Project Invariant 或后续 Framework Invariant，可以通过 `SUPERSEDED → PROPOSED` 使原 Guard 停止生效，同时又没有新的有效 `LOCKED` Guard 接管，而 Validator 仍报告：

```text
RESULT: PASS
exit code = 0
```

这可能把实际“保护已失效”的状态错误传递给 Pre-C04 / C04 / Release Evidence，属于可能造成 **Gate 错误和 Non-Regression 系统性失效** 的缺陷，符合 `S1 — Major`。

**关闭条件：**

新的精确 Review Target 必须提供可独立验证的证据，证明：

1. 对所有受 Contract 管理的适用 Invariant scope，而非仅当前四个硬编码 Framework ID，已不存在 `SUPERSEDED` 链终止于非有效 `LOCKED` successor 后仍返回 PASS 的情况；
2. `PROJECT` 的 `LOCKED → SUPERSEDED → PROPOSED` 负向案例必须 fail closed；
3. 后续新增的非 required `FRAMEWORK` Invariant 同类案例必须 fail closed；
4. 合法且最终存在有效 `LOCKED` successor 的 Supersession 不得被误拒；
5. 当前四个 required Framework Invariant 的既有保护不得回退；
6. 对该缺陷新增可重复的自动化 Regression Test；
7. 完整 Validator 回归集与正常 Target Validation 重新通过；
8. 新精确 Target 重新接受全新独立 C04 Session 复审。

本 C04 只规定必须满足的可验证关闭条件，不指定具体整改实现方案。

**所需证据：**

* 新的不可变 `REVIEW_TARGET_COMMIT`；
* `BASE..NEW_TARGET` 完整 Diff；
* 新增的 PROJECT Supersession fail-closed Regression Test；
* 新增的非 required FRAMEWORK Supersession fail-closed Regression Test，或能等价证明该范围已统一受到约束的自动化证据；
* 上述负向测试的实际退出码和输出；
* 正常 Contract Validation 的实际 `exit 0 / PASS` 证据；
* 完整 Validator test suite PASS；
* `git diff --check` PASS；
* 新 Target 的全新独立 C04 Review Record。

**REGRESSION_GUARD_DISPOSITION:** `REQUIRED`

理由：该缺陷具备明确输入、确定性输出、稳定复现条件和可自动判定结果，并且一旦复发会重新产生错误 Gate Evidence，满足机械 Regression Guard 的适用条件。
