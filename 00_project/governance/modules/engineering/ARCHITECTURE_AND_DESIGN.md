# 8. 架构决策必须使用 ADR 记录

对于会影响未来开发的重要技术选择，应创建 ADR。

例如：

```text
ADR-001-use-qt6.md
ADR-002-use-tcp.md
ADR-003-reconnect-strategy.md
ADR-004-local-storage.md
```

每份 ADR 至少写清：

```text
# ADR-xxx：标题

## 状态
Proposed / Accepted / Superseded / Rejected

## 背景
为什么需要做这个决定？

## 约束
有哪些已知限制？

## 候选方案
方案 A
方案 B
方案 C

## 最终决策
选择哪个方案？

## 决策理由
为什么选择它？

## 代价与缺点
这个方案有什么明显代价？

## 影响范围
影响哪些模块、接口、测试或部署？

## 重新评估条件
什么情况下未来允许重新考虑这个决定？
```

AI 不得在没有说明原因的情况下推翻已经 Accepted 的 ADR。

如果确实需要改变：

1. 创建新的 ADR；
2. 说明为什么旧决策不再适用；
3. 分析影响；
4. 更新相关需求、设计和测试；
5. 旧 ADR 标记为 Superseded。

# 9. 设计阶段必须进行 AI 独立质询

在以下阶段完成后，应进行独立评审：

1. 产品需求完成后；
2. 系统需求完成后；
3. 架构设计完成后；
4. 详细设计完成后；
5. 大型代码修改完成后。

推荐使用另一个 AI、另一个上下文或一个没有参与原设计的审查角色。

审查 AI 的任务不是“帮助原设计辩护”。

审查 AI 的任务是：

> **主动寻找可能导致返工、故障、维护困难、测试困难或产品失败的问题。**

重点检查：

- 需求遗漏；
- 需求冲突；
- 隐含假设；
- 边界条件；
- 异常路径；
- 状态机；
- 并发；
- 多线程；
- 生命周期；
- 资源释放；
- 内存安全；
- 网络异常；
- 数据一致性；
- 接口定义；
- 协议兼容；
- 升级兼容；
- 错误恢复；
- 日志和诊断；
- 性能瓶颈；
- 长期运行；
- 安全风险；
- 可维护性；
- 可测试性；
- 部署风险；
- 硬件实际约束；
- 真实使用环境。

# 10. AI 连续质询规则

独立质询时必须遵守以下规则：

1. 每次只问一个最重要的问题。
2. 用户回答后，再问下一个。
3. 已经能从现有文档明确得到答案的问题不要重复问。
4. 能可靠推导的问题不要浪费时间质询。
5. 优先问会影响当前：
   - 产品设计；
   - 技术路线；
   - 架构；
   - 接口；
   - 数据结构；
   - 状态机；
   - 代码结构；
   - 测试设计；
   - 当前开发工作的事项。
6. 当前阶段还不需要处理的问题，记录为“后续质询项”，不要提前无限展开。
7. 建议按 `QUESTION_PRIORITY` 分类：

```text
QUESTION_PRIORITY P0：不回答就无法继续正确设计
QUESTION_PRIORITY P1：不回答可能造成重大返工或架构错误
QUESTION_PRIORITY P2：会明显影响当前代码质量、测试或维护性
QUESTION_PRIORITY P3：以后优化即可，当前可以暂缓
```

当前质询主要处理 `QUESTION_PRIORITY` P0、P1、P2。

结束条件：

> 当前阶段不存在尚未闭环、并且会显著影响产品设计、技术路线、接口、数据结构、软件架构、测试方案或当前代码实现的重大问题。

# 11. 质询必须形成正式记录

建议保存到：

```text
05_reviews/ai_challenge_records/
```

每个重要问题至少记录：

```text
Q-017

问题：
网络长期不可用时，系统是否允许无限重连？

为什么现在必须回答：
会直接影响状态机、资源使用、日志策略和现场故障处理。

用户回答：
不允许。

最终决策：
连续失败 30 分钟后进入 Fault 状态。

影响：
SYS-NET-011
ARCH-NET-005
DES-NET-021
TC-NET-033

需要修改的文档：
...
```

# 12. 详细设计必须先于正式编码

正式编码前，至少应明确：

- 模块边界；
- 模块职责；
- 公共接口；
- 输入；
- 输出；
- 数据结构；
- 状态机；
- 错误处理；
- 超时策略；
- 重试策略；
- 生命周期；
- 线程模型；
- 资源所有权；
- 配置；
- 日志；
- 数据持久化；
- 关键算法；
- 性能限制；
- 测试方法。

AI 不应仅凭一个模糊需求直接构建大量代码。

# 13. 测试设计与测试代码必须分开

必须区分：

```text
06_test_design/
```

和：

```text
08_tests/
```

前者回答：

> 应该测试什么？

后者回答：

> 测试具体如何自动执行？

例如：

测试设计：

```text
REL-001：
系统连续运行 7 天不得发生进程异常退出。
```

测试程序可能是：

```text
08_tests/system/test_long_running.py
```
